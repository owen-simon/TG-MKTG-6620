Skill Workshop — Turn Course Methods into Reusable Skills

MKTG 6620 · Model comparison, k-means, trees, and forecasting

Build one reusable skill from an analysis you understand, test it on a small example, and revise it using the results. The four examples cover model comparison, k-means with optional PCA, tree classification, and time-series forecasting.

What you need: your usual coding agent and a practice folder. This handout contains all four example skills, prompts, and test cases. To start from the editable files, extract S4_skill_workshop_files.zip; its skill_examples/ folder contains one SKILL.md for each method.

This is ungraded practice. Finish with one revised skill and a short test record. Case 1 and Case 2 keep their existing requirements and deadlines; assessed interpretations and memos remain your own writing.

1. Decide what belongs in a skill

A prompt specifies today's request. A skill carries reusable instructions for requests of a certain kind. A Python script performs a calculation. The agent can read a skill and use or write code to carry out the request. Start with one instruction file; add a script when repeated calculations benefit from a tested implementation.

A lean skill contains decisions another capable agent might otherwise get wrong. It does not need to explain Python, repeat the entire lecture, insist on one winner, or force every dataset through one set of dates and settings. The class examples below are roughly a page each. Their length is a design choice, not a universal word limit.

Keep in the skill Put in today's prompt or assignment
Use validation for selection and reserve later evaluation Today's files, outcome, metric, candidates, and split dates
Keep IDs out of clustering distance Today's customer ID column and chosen features
Check whether an input exists before a decision Today's decision time and available columns
Construct fixed-origin forecasts from earlier data Today's origin, horizon, and approved history length
Return evidence the user can inspect Today's output folder and requested formats

For coursework, the task contract also tells the agent which writing must remain yours. A skill cannot override that rule.

2. Write the trigger before the body

Compare these descriptions:

  • Too broad: “Help with all marketing analytics and make the best model.”
  • Useful: “Compare a bounded set of model specifications for a stated business prediction task, using a baseline and separate selection and evaluation evidence.”

The useful description tells an agent when this skill applies. A request to format a chart caption should not trigger model fitting. Overlap is acceptable: compare-model-specs governs the comparison, while tree-classification contributes method-specific checks. The assignment supplies the current scope.

The standard file starts with YAML metadata:

---
name: compare-model-specs
description: Compare a bounded set of model specifications for a stated business prediction task, using a baseline and separate selection and evaluation evidence.
---

Below that header, write the reusable procedure in ordinary Markdown. Name, description, and body are enough for these examples. Optional helper folders are not required. Skill hosts can first inspect the name and description, then read the body when the task matches. This is called progressive disclosure: load more detail when it is needed. Official skill guide

3. Extract a skill from work you understand

Help me design a lean skill for comparing model specifications.
Use the workflow from our course: task and baseline, common evaluation
rows, training-only fitting, validation selection, later evaluation,
paired comparisons, and inspectable outputs. First propose a precise
name and description. Then draft one SKILL.md. Keep today's dataset,
dates, candidate count, and numerical results out of the reusable
instructions. Follow the assignment's AI-use rules. Explain why each
instruction changes a decision the agent might otherwise get wrong.

Read every sentence. Mark it keep, move to today's prompt, or remove. Keep the few instructions that change behavior. Move current file names, hyperparameters, and dates to the invocation. Remove “be accurate,” long background lectures, and claims that the skill guarantees the right answer.

In the clustering example, n_init is the number of random initializations; ARI compares grouping agreement even when the numeric cluster labels change.

Now apply the same process to k-means, trees, and time-series forecasting. The four completed examples below are editable starting points. First identify one decision each must preserve, then compare your draft with the example.

Example — Model specification selection

Save as compare-model-specs/SKILL.md.

---
name: compare-model-specs
description: Compare a bounded set of model specifications for a stated business prediction task, using a baseline and separate selection and evaluation evidence.
---

Read the assignment or task contract first. Identify the decision, row unit,
outcome, usable inputs, baseline, candidates, primary metric, and compute budget.
Ask only for missing choices that would change the comparison. Use supplied
methods when the task supplies them; do not expand the search automatically.

Keep candidate methods on the same evaluation rows. Use time-ordered evaluation
for future prediction and keep repeated entities together when needed. Learn
preprocessing from training data. Select using validation evidence, record the
choice, then evaluate it on the reserved test data. Do not use test results to
retune and still call that sample untouched.

Return a table of every attempted specification, its choices, validation result,
and status. Add final-test results only after selection. Compare differences on
the same resamples, at a unit appropriate to the data's dependence. State what
the interval includes and omits. An interval containing zero does not establish
equivalence; a small observed win does not establish business value.

Save code, versions, data identifiers, splits, and outputs. Surface tradeoffs
for the user to decide. For assessed coursework, generate calculations and
explanations for learning, but leave assessed interpretations and memos to the
student under the assignment's AI-use policy.

Example — K-means and optional PCA

Save as kmeans-segments/SKILL.md.

---
name: kmeans-segments
description: Build and assess customer segments with k-means, including feature and scaling choices, optional PCA, cluster profiles, and stability checks.
---

Read the segmentation decision and available fields. State the customer unit,
selected features, missing-value and outlier policies, transformations, scaling,
candidate k values, seed, and n_init. Keep identifiers and outcome labels out of
the distance calculation. Preserve requested settings and a bounded run budget.

Explain which differences drive distance. If using PCA, fit it after the chosen
preprocessing and report retained variance and loadings. PCA components summarize
variation; they are not automatically customer motivations.

Fit the requested candidates. Report silhouette with cluster sizes and profiles
in original units. Compare membership across a few stated seeds or resamples
using an agreement measure unaffected by cluster-number permutations. Do not
compare numeric cluster labels directly. Use a null comparison when the question
requires evidence beyond geometric separation; match its preprocessing and
search procedure to the observed analysis.

Explain whether segments identify an actionable distinction or mostly separate
high from low values on one variable. High silhouette and stable membership do
not prove natural customer types or different responses to marketing.

Return the settings table, membership file keyed by customer ID, profiles,
diagnostics, and limitations. Do not turn a proposed segment treatment into a
measured causal effect. Respect the assignment's rules on student-authored work.

Example — Trees and classification

Save as tree-classification/SKILL.md.

---
name: tree-classification
description: Fit or compare decision trees and tree ensembles for classification, checking input timing, held-out ranking, contact capacity, and probability accuracy.
---

Read the task's outcome, positive class, decision time, capacity, baseline, and
allowed methods. Check whether every input exists when the decision is made.
Exclude identifiers and information learned afterward unless the task gives a
valid reason to use them. Completed-call duration cannot guide a pre-call list.

Use the task's split and settings. Fit encoding, scaling where needed, and models
on training rows only. Compare candidates on validation rows, record selection,
and evaluate afterward. Keep final-test data out of tuning. If time or repeated
customers make a random row split unsuitable, surface that before fitting.

Return AUC alongside the observed positive rate at the stated contact capacity.
Keep the contact count within capacity and break score ties without outcomes.
Check predicted against observed rates overall, in the selected list, and across
probability groups; include group counts. AUC assesses ranking, not calibration.

For model differences, use the same resampled evaluation units for both models
and state the uncertainty covered. Keep feature importance separate from causal
effects. Churn risk is not the effect of a retention offer. Report business value
only under explicit cost and intervention assumptions. Preserve all results and
the assignment's boundary around student-written interpretations and memos.

Example — Time series and foundation models

Save as time-series-forecast/SKILL.md.

---
name: time-series-forecast
description: Compare time-series forecasts at fixed origins and horizons, including seasonal baselines, fitted methods, and supplied or locally run foundation-model forecasts.
---

State the series key, target units, frequency, forecast origins, horizon, history
window, and information available at each origin. Check duplicate keys and
missing dates. An absent row is not automatically zero demand. Learn any fill
rule from history and disclose it; do not fill unknown evaluation outcomes.

Build the baseline from information available at the origin. For seasonal naive,
repeat the last complete training week throughout the horizon. Never read later
actuals to refresh a fixed-origin forecast. Fit other methods on history only.
Use a known future calendar only under an explicit availability assumption.

Select on earlier validation windows and preserve a later evaluation window.
Compare common rows with MAE and a defined denominator, such as WAPE. Report
counts and undefined cases. MASE uses training seasonal-difference errors; its
value of one need not tie the baseline on this test window.

For foundation forecasts, record model revision, context, output meaning, and
whether predictions were supplied or generated. Check quantile ordering and
coverage with denominators. Do not sum daily quantiles into a total-demand
quantile. Preserve dependent observations when resampling model differences.

Return forecasts keyed by origin, date, and series; comparison tables; checks;
and limits. Do not install, download, or call services without task authorization.
Respect coursework rules on student-written judgments.

4. Give the skill a home and invoke it

For Codex in your own practice repository, put the chosen folder inside .agents/skills/. For example:

my-practice-project/
  .agents/
    skills/
      time-series-forecast/
        SKILL.md

The workshop ZIP stores examples in a visible skill_examples/ folder so you can inspect them first. Copy only the skill folders you want into your own repository. Do not put them into a system directory or overwrite an existing skill without comparing it.

In Codex, mention $time-series-forecast in the task prompt. If your chosen agent uses a different skill location, use its documented mechanism. The portable fallback is to attach or explicitly ask it to read the SKILL.md file. This exercises the instructions even when automatic discovery is not available. Codex discovery and invocation

Use $time-series-forecast for this practice task. Read the Session 4
handout and local sales and foundation-forecast files. Use its three
origins, 15-day horizon, and bounded three-method comparison. Start
with the date audit and stop after the two validation windows. Save
code and evidence I can inspect. Tell me which skill you read and
which task-specific choices came from the handout.

The agent's claim that it read a skill is only one clue. Inspect whether the result actually respects the dates, uses the keys, and stops before the final evaluation. Installed does not mean followed; followed does not mean correct.

5. Test behavior, then revise one instruction

Use the following small tests in a fresh practice conversation. Give the agent the request and the skill; inspect artifacts rather than grading its tone. All numbers in this table are invented practice inputs.

Skill Ordinary request Tricky request and the evidence to look for Outside its scope
Model specification selection Compare baseline A and candidate B on the supplied validation table. Validation AUC: A .80, B .79; test AUC: A .77, B .84. Ask which was selected by a highest-validation-AUC rule. It should preserve A, report the later reversal, and avoid inventing an earlier selection of B. Reformat a paragraph; it should not start a model search.
K-means Segment numeric customer features with a stated k and scaling. IDs [1,2,3,4], spending [10,11,90,91], labels from two runs [0,0,1,1] and [1,1,0,0]. IDs must stay outside the distance; identical grouping has ARI 1 despite label reversal. Predict a labelled churn outcome; grouping is not a replacement for classification.
Tree classification Compare the assigned classifier and baseline at a fixed capacity. A pre-call list includes completed-call duration. It should exclude that field from a deployable comparison and explain why. With 9 customers and at most 20% capacity, it contacts at most 1, not 2. Estimate the causal effect of a retention offer from churn labels alone.
Time series Forecast 15 days from a seven-value training week. Supply [10,20,30,40,50,60,70], then change a future actual to 999. Day-8 forecast must remain 10. With all actuals zero and forecasts 2, MAE is 2 and WAPE is undefined. Turn a revenue forecast directly into staff headcount without a staffing relationship.

The specification-selection toy supplies both tables. It tests application of the stated rule; it does not recreate an unseen final evaluation or prove that a choice was made prospectively.

For each test, record the request, the skill version, what happened, the file or calculation you checked, and the smallest useful revision. If the first version succeeds, record that success. There is no requirement to make an agent fail. If the task cannot be executed, distinguish a discussion of what should happen from a completed behavior test.

Test my draft skill on one ordinary request and one tricky case
from the workshop. Use a new scratch folder and no external services.
Show the resulting files and checks. Identify one instruction that
helped or one observed failure. Propose the smallest revision that
addresses the evidence. If both tests pass, do not invent a failure
or add rules just to make the skill longer.

6. Explain your design to another analyst

In your practice notes, answer: When should this skill be used? Which two analytical decisions does it protect? What evidence does it return? Which choice still belongs to the current user? What did your test establish?

A useful finished exercise is one revised skill and a short test record. The four examples let you repeat the exercise across the course methods. These notes are ungraded practice. You may use the skills to help with the permitted parts of Case 1 and Case 2, while writing assessed judgments yourself.
